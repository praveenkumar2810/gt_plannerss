GT field collection protocol
Standard operating guidelines for field teams — Sentinel-2 10m bands
◆

Minimum sample size

Per crop per agro-climatic zone: ≥30 pure-crop polygons or ≥50 GPS points. For rare crops (millets, specialty pulses) ≥20 is acceptable. Ensure spatial distribution across soil types and irrigation classes (rainfed vs. irrigated).

■

Polygon vs. point collection

Collect field boundary polygons, not just centroids. For fields <0.5 ha collect center-point + area estimate. For fields >1 ha walk the boundary with a smartphone GPS or handheld GNSS. Each GT point must represent a pure 3×3 pixel (30m×30m) area — maintain >30m buffer from field edge for S2 10m bands.

▲

Mandatory attributes

Crop name (local + botanical), variety if known, sowing date (approximate), irrigation type (rainfed / canal / borewell / drip), growth stage at visit time, intercrop or mixed crop status, field size estimate, and a geotagged photograph.

●

Satellite pass sync

Plan field visits 0–2 days AFTER a confirmed cloud-free S2 pass. Check 7-day weather forecast before mobilizing. For Kharif, identify 2–3 alternate S2 acquisition dates within your 45-day window as monsoon backup. SAR (Sentinel-1) can fill cloud gaps.

◆

Mixed crop handling

Flag all mixed-crop and intercrop fields with a "MIXED" tag. Exclude from primary training set unless building a mixed-crop class. Record the dominant + secondary crop combination for potential mixed-class use.

■

Spatial sampling strategy

Never sample roadside fields only — this creates systematic bias toward irrigated, accessible plots. Use a stratified random sampling grid for site selection. Cover all tehsils in the target district, not just accessible talukas.

●

Crop code standardization

All teams must use the same standardized crop code list + local name lookup table before departure. Single enumerator naming leads to duplicates (e.g. "Dhan" vs "Paddy" vs "Rice"). Use FASAL or ICAR crop codes as reference.

▲

Quality control in field

Each GT point must have: (1) geotagged photo, (2) crop verified by local farmer if possible, (3) NDVI visual check — avoid fields with NDVI <0.3 (sparse/stressed canopy, poor spectral quality). Flag any field narrower than 50m as "edge risk" for S2.

Common GT mistakes and mitigation
Avoid these pitfalls to maintain training data quality
MistakeImpact on classificationFix
Visiting too early — July for Kharif Bare soil signal dominates; poor spectral separability; NDVI <0.3 Wait for canopy closure. Check NDVI >0.5 in field before collecting points
Visiting during harvest — Oct for Kharif Crop already cut; GT points represent stubble/bare soil not crop Check local harvest calendar before scheduling. Visit before 70% of area is harvested
Roadside / accessible field bias Irrigated, high-input fields over-represented; classifier fails on rainfed areas Use systematic random sampling grid. Cover all land-use gradients and soil types
No photograph documentation GT quality unverifiable during post-processing and QC review Mandatory geotagged photo for every GT point. Store in same folder as GPS data
Ignoring mixed crops / intercropping Mixed pixels corrupt classifier training; spectral confusion between classes Flag and exclude from primary training set OR create dedicated "mixed" class
Inconsistent crop naming across teams Duplicate classes in training data; breaks label encoder in ML pipeline Standardize to crop code list + local name lookup table before field departure
GPS points too close to field edge Edge pixels mix crop spectral signature with bunds, roads, water channels Maintain >30m buffer from field edge for all S2 GT points (3 pixel minimum)
Over-sampling dominant crops (paddy, wheat) Class imbalance; minority crops (pulses, oilseeds) poorly classified Set per-crop quotas. Allocate extra effort to minority crops even if harder to find
